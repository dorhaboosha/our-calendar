# Acceptance criteria: where each one is checked

The 22 criteria of spec section 14, each with the automated tests that check it and the
check on the live site. Gone through on **2026-11-28**, at the end of Phase 5.

- **Unit:** `src/**/*.test.ts`. **Integration:** `tests/integration` (a real Postgres,
  and a fake Google, [`fake-google.ts`](../tests/integration/fake-google.ts)).
  **E2E:** `tests/e2e` (Playwright, the production build, desktop and phone).
- **Live** checks are done on https://our-calendar-ay05.onrender.com with the real
  Google accounts after each phase is deployed. "After merging" items are on the
  Phase 5 live check list below.

## Phase 5 live check (after merging)

1. Install on both phones (Android and iPhone): name, icon, no browser bar.
2. Leave the app, add an event from the other phone, come back: it shows. Airplane
   mode: the notice shows, and goes once the connection is back.
3. In Google, edit one occurrence of a repeating event and delete another; "export
   again" sets both back (Google's real listing of changed occurrences, and PUT bringing
   back a deleted occurrence). Then change the series' title in the app: both
   occurrences take the new title too.
4. "Export again" with every event: how long it takes, and the count going down.
5. Rename the app on Google's consent screen to OurCalendar (name only).
6. A few days after merging: the scheduled export runs at 7 and 37 minutes past, and how
   often it really runs (see [operations](operations.md#measured-use)); Neon's compute
   sleeps between runs.
